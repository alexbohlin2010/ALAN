## Method

- **Independence and order.** a01 (start) -> a02 -> a03 -> a04 -> a05 -> a06 were written and run **before** `pipeline/spectra/01_night_spectra.py` was opened; then the script was read; then a01 (end). a02 has its own parser (plain `split`, no `csv` module, asserts no CR/quotes), its own selection (exact integer round-half-up, cross-checked with float `floor(x+0.5)`), and its own percentile. It imports nothing from `pipeline/`. The output JSONs were inspected only for their structure before a02 was written.
- a03 reads output JSON number literals as text (`json.load(..., parse_float=str, parse_int=str)`) so source-text identity is tested directly, then compares as floats.
- a05 reads the draft's output read-only from the main checkout (outside this worktree).
- All scripts run from `final/` with system `python3`, stdlib only. The pipeline script was **not** run (it would rewrite `data/derived/`).

The script writes only the three files in `data/derived/spectra/` and opens raw files read-only.

## Findings (concerning or worth a human look; not failures of the stated rules)

- **F1. `night_id` text changed.** Source `1`..`9` is written as `1.0`..`9.0` (float-equal). Rule 4 (verbatim) is stated for irradiance only; elevations and fraction happen to round-trip to the identical text.
- **F2. Source row 2 is not one value per night.** In both files the row-2 value steps up at about 01:05 (source timestamp, no time zone) inside a continuous night block: Phil. 1->2 (06-Jul 01:06), 6->7 (17-Jul 01:06), 8->9 (18-Jul 01:06); CSSP 1->2 (01-Jul 01:05), 4->5 (03-Jul 01:05), 8->9 (19-Jul 01:06). So the 5 night blocks per site carry 8 distinct `night_id` values. MANIFEST calls row 2 "date/night"; the outputs call it `night_id`.
- **F3. Units not inside the site files.** `philadelphia.json` / `cherry_springs.json` have no unit, wavelength axis, source URL or time-zone field; these are only in `spectra_meta.json` in the same folder (a code comment in the script says so, the files themselves do not).
- **F4. Unlabelled site-file fields.** `labels` covers 7 entries; these keys have none: `site`, `place`, `paper_label`, `source_file`, `source_sha256`, `n_source_spectra`, `n_night_spectra`, `n_selected`, `source_date_range`, `selected_date_range`, `source_dataquality`, `selected_cells`, `source_column`. `display_limits_log10` is labelled in the meta file only.
- **F5. Draft reference not in the repo.** `spectra_meta.json` "reproduces" points to `Linda/visual tests/spatial/philadelphia-spectral-space/scripts/preprocess.ts`; that folder exists in the main checkout but is not tracked by git (`git ls-files` returns nothing for it) and is absent from this worktree.
- **F6. Wavelength assignment is documentary.** The raw CSVs have no wavelength row; 280-840 nm at 1 nm comes from the MANIFEST note / repo README (Table S1). 566 - 5 = 561 rows is consistent with it.
- **Facts for context (no rule broken):** selected spectra per night block Phil. [54, 40, 15, 65, 66], CSSP [57, 49, 55, 16, 63]; moon above horizon in 169/240 (Phil.) and 67/240 (CSSP) selected spectra (moon not considered by human decision; the handoff 2026-10-04_two-nights-spectra.md records this). Output zeros concentrate at 282-314 nm (CSSP up to 155 of 240 spectra at 314 nm).
- **Script risk notes.** R1: the verbatim trick (`rsplit('"irradiance":')` then delete every `"` in the tail) relies on `irradiance` being the last key and on every token being a valid JSON number; the post-write check uses Python's lenient `json.loads`, which would accept `NaN`/`Infinity` tokens. Not triggered here (all selected tokens are `0` or `d.ddde-NN` forms; strict parse passes). R2: the file is written before that check, so a failing check would leave an invalid file on disk. R3: `even_sample` silently returns fewer than 240 spectra if a site has <= 240 night spectra (not the case here).
